## Behavioural notes

1. **Bookmark bundle:** Existing v1 importers keep working — combined envelope only emitted when `views` is non-empty. Filename gets a clearer `particle-scenes+views-YYYY-MM-DD.json` suffix when both lists ship.
2. **Wind/crossfade overrides:** Each slot has its own per-id localStorage entry; the live preset arrays are mutated in place so `matchesWindPreset` / `matchDurationChip` automatically highlight the overridden chip when the slider lands on its custom value. Reset surfaces as a small ↺ badge on overridden chips — one tap reverts.
3. **Lightbox zoom:** Sign convention matches every major browser. Wheel-zoom anchors at cursor (zoom-to-mouse feels native). Keyboard zoom centres on the stage. Both share the same `applyZoomBy` math as the pinch state machine, so all three input paths land in the same place.
4. **Minimap tooltip:** `tooltipPlacement` defaults to ABOVE the dot, flips BELOW near the top edge, slides into bounds near the side edges. Hover hit-radius (10px) is slightly more generous than the click hit-radius (8px) so the label catches before the click does. `hoverName` is captured at hover-time so the render path never reads `viewsRef.current` (react-hooks/refs rule).

## Lint catch worth flagging

Initial Minimap.jsx implementation read `viewsRef.current.find(...)` during render to look up the hovered view's friendly name — caught by `react-hooks/refs` during the gate. Refactored to capture the name into React state at `onMouseMove` time alongside the placement, which is what the rule wants and is cleaner anyway (no stale-closure window between hover and render).
