## Notes on R28.43 implementation drift caught mid-build

Initial choice of `easeOutCubic` for the recommended curve was wrong
for the roadmap's stated goal. easeOutCubic is t' = 1 - (1-t)^3, which
produces FAST fade in the first half (badge greys quickly then
lingers) — the OPPOSITE of "slow first 500ms, fast last 500ms". The
correct curve for the roadmap requirement is `easeInCubic` (t' = t^3):
at t=0.5 the colour has only walked 12.5% toward grey, meaning the
badge stays visibly bright through the first half then rushes to grey
in the last half. Caught while writing the semantic-check test that
exercises this exact property — the test forced me to articulate
which curve was UNDER the diagonal at midpoint, and the answer
flipped my recommended constant. Both curves stay in the roster as
options; only the recommendation changed.
