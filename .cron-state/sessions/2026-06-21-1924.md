## What landed (one paragraph each)

**R14.05 — Named attractor type-specific colour cues.** Each force-
field type now has a distinct accent across the entire UI:
attractor=indigo, repulsor=red, vortex=violet, turbulence=amber.
Lives in a small `ATTRACTOR_TYPE_STYLES` table + `attractorTypeStyle
(type)` helper in namedAttractors.js — returns a complete CSS-ready
bundle (border at 0.45/0.30/0.18 alpha, bg at 0.14/0.06/0.03, fg=
accent hex, glow). Unknown/null types fall back to indigo so a stale
localStorage entry never paints a borderless ghost. UI wiring:
LeftSidebar NamedAttractorRow's row border + #index badge wear the
type accent; the type chip grid uses each type's own colour as its
active state (so the active Repulsor chip is red, active Turbulence
chip is amber, etc); MidiPanel per-attractor group header pulls the
LIVE attractor from useStore and paints its border + adds a small
coloured dot + a monospace lowercased type-name suffix; stale groups
(deleted attractor still has bindings) fall back to the previous
violet "missing" tone. Tests cover 4-distinct-accent assertion +
palette pins + full bundle field completeness for every type +
fallback for unknown/null/undefined + opacity hierarchy walk.

**R14.15 — Wind override import preview panel.** Wind override
import was a fire-and-forget pair of merge/replace buttons; pick the
wrong one and you'd silently wipe carefully-tuned chips. Now: the
import buttons stage a preview panel below them, and applying is
gated behind explicit Apply Merge / Apply Replace. The preview reuses
the already-tested `summarizeImportImpact` from windOverridesIO.js
for the counts, builds a diff list with one row per slot ordered by
WIND_PRESETS_DEFAULT (calm → breeze → gale → storm), shows
`intensity/azimuth°` chips for live vs. incoming with three action
states (add=emerald, overwrite=amber+OVR badge, skip=muted+SKIP
badge), and has a mode-aware impact line + Apply gated on willWrite
> 0 in merge mode. Directly parallels the keymap import preview from
R13.04.

**R14.16 — Crossfade override import preview panel.** Direct parallel
of R14.15 for crossfade chip overrides. Same staging pattern, same
action badges, same mode-aware impact line. One nice touch: when a
slot has no live override the live cell shows the SHIPPED DEFAULT in
italics with a tooltip explaining what the chip would use without an
override — gives users context for what their incoming value will
displace. Pink-violet panel matches the existing Crossfade chip
colours so it visually belongs.

**R14.17 — MIDI user bundle export/import as portable JSON.** User-
authored MIDI bundles (R13.05) were machine-local: save a "Stage
Rig" bundle at home, walk to a laptop, and you'd have to Learn-tap
every CC again. Now any saved bundle ships as a tiny JSON file
(`particle-midi-bundle-<slug>-<date>.json`, slugified from the
bundle name) and imports in one click. New module `midiUserBundleIO
.js` (kind=`ai-particle-simulator/midi-user-bundle`, v1, 16 KB cap)
with envelope build/parse/serialize/makeFilename/parseImport
/isAtBundleCap/downloadUserBundleFile; tolerates a bare-bundle
shorthand on import for hand-rolled files. The id, vendor, and
createdAt fields are STRIPPED on round-trip so two machines exporting
+ re-importing can't collide on numbered ids — the importer mints
fresh. Per-bundle Download (indigo) button tucked between the apply
chip + trash on each "Your Bundles" chip row; "+ Import bundle"
button (Upload icon, indigo) paired with the existing "+ Save current
as bundle" below the bar so a fresh install can pick up a friend's
bundle without first having to save one of their own. Cap-gated to
prevent silent FIFO drops.

**R14.18 — MIDI user bundle rename in-place.** Previously rename =
delete + re-save. Now: double-click the bundle chip's name to enter
edit mode; Enter saves, Escape cancels, blur saves with blank-
fallback-to-cancel. New `renameUserPreset(list, id, newName)` helper
in midiPresets.js with ref-equal-on-no-op contract (blank-after-trim,
missing id, identical name, non-array list, null/undefined inputs
all return the same list ref). When the description still matches
the auto-generated template `<N> binding(s) saved YYYY-MM-DD`, the
rename also rewrites it to carry the same form using `createdAt`'s
date. When the description has been hand-edited, it's PRESERVED.
Extracted the inline user-bundle row into a new `UserBundleChip` leaf
component so the editing state machine + autoFocus input ref live
in one place; matches the NamedAttractorRow rename gesture in
LeftSidebar.

## What I'd flag to Sanjay next time he looks
- The R14.15 + R14.16 preview panels use `summarizeImportImpact`
  shapes that already existed in the IO modules — the previews were
  blocked only by UI work, not by the lib. This is the cheapest kind
  of slice; we should look for more "lib helper exists, UI doesn't
  use it yet" gaps in the next batch.
- The R14.05 type-cue palette could probably propagate further:
  scene bookmarks list could badge "vortex + repulsor" scenes with
  those colours; the minimap could tint attractor dots by their
  type; the MIDI auto-CC indicator at the top of each row could
  carry a tiny coloured dot.
- The bundle cap of 8 is still hard-coded. With export/import
  landed, users now have a reason to want more than 8 simultaneously
  on disk (the file system is their real archive); the cap could
  grow to 16 or 24 without UX cost.
