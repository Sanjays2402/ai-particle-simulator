## What landed

1. **R17.20 — Lightbox pan accel curve preset chip** (21f15f1)
   Graduates the R16.20 single-shape acceleration ramp with four chip-
   cycled curves: linear (default, R16.20 baseline), exp (t² — slow
   start, sprint finish), log (sqrt(t) — fast help early, then settle),
   off (acceleration disabled entirely). New pure helpers
   `PAN_ACCEL_CURVES` + `nextPanAccelCurve(current)` in pinchZoom.js;
   `panAccelMultiplier` extended with `opts.curve` passthrough;
   `scaleDirByHold` threads `opts.curve` so existing callsites only
   change at the threading layer. Endpoint convergence preserved
   across every curve so swapping curves never overshoots MAX or
   dips below 1×; monotonicity preserved on input. Persisted via
   `setLightboxPanCurve` (key `lightbox-pan-curve-v1`); parallels
   R16.17 `spectrumPeakCurve` for UX consistency. SnapshotGallery
   `panCurveRef` mirrors the store value so the hold-keys 60ms tick
   re-reads the live curve — flipping mid-sweep reshapes in real time.

2. **R17.15 — Per-attractor MIDI radius·log routing** (fb8d794)
   Adds sibling `attr:<id>:radiusLog` slot next to linear
   `attr:<id>:radius` so users can pick the knob feel that matches
   their hardware. Curve `2^v - 1` maps v01 ∈ [0,1] to [0,1] with
   midpoint ≈0.414: knob bottom half covers radii 4..8 (fine control
   at the low end where small radius changes have the biggest visible
   effect), top half flows up through 8..16. Both rows live side-by-
   side in the MidiPanel per-attractor section. New pure helpers
   `logCurveShape` + `logCurveRadius` in midiMap.js with full
   defensive contract. `ATTRACTOR_FIELDS` grew 6→7 entries.

3. **R17.17 — Named attractor bulk-delete via shift-click** (a927c8d)
   Graduates the single-× delete with a multi-select bar that
   surfaces above the list as soon as one row is selected; offers
   Select all / Clear / Delete N (gradient red, window.confirm gate).
   Shift-click on any row toggles selection; selected rows wear red
   border + glow + on-row checkbox. Selection auto-reconciles via
   `useMemo(validSelectedIds)` derived value (no setState-in-effect)
   so ids that vanish externally drop silently. New pure helper
   `removeAttractors(list, idSet)` accepts Set | Array | iterable
   (incl. generators), normalises to Set internally for O(1) hits,
   ref-equal-on-no-op contract preserved.

4. **R17.07 — Camera path drag-and-drop reorder** (62bacfa)
   Graduates the chevron up/down buttons (R10.03) with a direct drag
   gesture. The chevrons stay (precision + keyboard-only users). Pure
   wire layer on top of `moveView(views, fromIdx, toIdx)` so no new
   lib helpers / no new unit tests. `draggingIdx` kept in STATE
   (not REF) since each row reads it during render to compute its
   `isBeingDragged` styling, and react-hooks/refs disallows reading
   refs during render. Sibling-enter-before-leave guard prevents
   the indicator from flickering across row boundaries.

5. **R17.06 — Custom theme pack drag-and-drop import** (afc5a6f)
   Graduates the click-to-import button with a file-drop zone
   covering the entire CustomThemesRow block. Drop a .json theme
   pack anywhere on the row and the same R10.10 preview panel
   surfaces (no auto-apply — every import still flows through the
   Merge/Replace dry-run summary). `dragDepth` counter handles
   nested dragenter/leave so the highlight doesn't flicker across
   child elements. Filters by `dataTransfer.types.includes('Files')`
   so stray text-drags don't trigger. Multi-file drops read the
   FIRST file only (single-file convention); non-.json files toast
   an error. Shared `parseAndPreview(file)` with the file-picker
   path so a future format change touches one place.
