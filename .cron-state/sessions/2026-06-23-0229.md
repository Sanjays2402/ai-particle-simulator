### R23.33 — Bias drag-drop accepts multiple .json files

**Graduates:** R22.28 (single-file bias drag-drop).

**Why:** R22.28 dropped only the first .json in a multi-file gesture,
silently discarding the rest. Friend-collection imports failed quietly;
no per-file feedback when one file in a batch was corrupt.

**Lib:** New `combineDroppedBiasFiles(reads)` in biasOverridesIO.js.
Takes per-file FileReader results `{ raw, error?, name? }`, runs each
through `parseImport`, per-file failures counted but never abort
(partial success preserved), cross-file conflicts resolve last-file-
wins (caller sorts alphabetically for deterministic behaviour across
machines). Returns `{ items, parseFails, totalFilesRead, perFile }`
where perFile is one `{ name, ok, chipCount }` | `{ name, ok:false, error }`
per attempted file. `chipCount` reflects post-sanitize count so unknown
chip ids dropped via `sanitizeBiasOverridesMap` don't inflate the
summary.

**UI:** `onBiasDrop` filters to .json files first, sorts alphabetically,
reads in parallel via `Promise.all`, then feeds into the combiner.
New `applyCombinedBiasItems` shares the confirm + merge + persist
sequence with the single-file path; toast wording mentions file count
when > 1, parse-fail count when > 0. Drop banner gains "(multi-file ok)"
hint.

**Tests:** ~70 fresh asserts. Happy multi-file + cross-file last-file-
wins + partial success (1 valid + 1 corrupt) + defensive (null/string/
empty/non-object inputs) + reads with error field set + wrong-kind
envelope partial taint + name-missing → 'unnamed' placeholder +
sanitize pass drops unknown chips + purity (no input mutation).

### R23.34 — Carousel filter by thumbnail note text

**Graduates:** R22.29 (per-tile editable note).

**Why:** R22.29 let users attach free-form notes to thumbnails
("good demo shot", "wrong colors") but there was no way to find them
back — a user with 30 tagged thumbs had to eyeball-scan to surface
them. Substring search closes that loop.

**Lib:** New helpers in presetThumbnails.js:
- `normalizeNoteQuery(raw)` — trim + lowercase. Non-string/nullish/
  whitespace → empty string. UI uses this to gate the filter
  consistently with the matcher.
- `noteMatchesQuery(note, raw)` — substring + case-insensitive. Empty
  query matches every non-empty note (composeable for list filters).
  Non-string note → no match (defensive against corrupt persisted
  values).
- `presetsMatchingNote(presets, raw, storage?)` — projects a preset
  list to the subset whose stored note matches. **Empty/null/whitespace
  query returns the input array BY REFERENCE** — no-op semantics so
  the carousel renders the full list without a special-case branch.
  Non-array presets / missing storage → []. Order preserved; malformed
  entries / note-less tiles skipped silently.
- `summarizeNoteFilter(presets, raw, storage?)` — count-only projection
  returning `{ matching, totalWithNotes }` so the UI can render
  "12 of 24 tagged" without allocating the output array.

**UI:** Note-filter chip + collapsible input next to the bulk-rebuild
button. Only renders when at least one tile in the FULL preset list
has a saved note (no point offering search across zero hits). Click
chip opens an inline input (autofocus). Live match-count badge "12/24"
updates as the user types.
- Esc clears AND closes (panic-out path)
- Enter dismisses input keeping query
- × clears just query
- ✕ closes input keeping filter applied
- Chip wears amber accent when query active (orthogonal to purple
  category-filter accent)
- Note filter intersects with existing tri-state category filter
  (All / Favs / Recent) — power users can stack "Favs + 'demo'"
- Empty-results banner when query is active but no tiles match —
  friendly inline message instead of empty carousel

**Tests:** ~60 fresh asserts. normalizeNoteQuery (trim+lowercase, non-
string fallback), noteMatchesQuery (substring case-insensitive, empty
query semantics, defensive note types), presetsMatchingNote (happy
path, case mix, substring boundary, empty-query no-op preserves
ref-equality, defensive presets/storage, malformed entries skipped,
note-less skipped, order preserved), summarizeNoteFilter (matching +
totalWithNotes invariants), trim invariant between record/read/match.

### R23.35 — MIDI hotkey-conflict UNDO chains (toggle)

**Graduates:** R22.30 (single-shot Undo on the hotkey-conflict toast).

**Why:** R22.30 surfaced an Undo chip on the strip toast so users
could roll back a stolen hotkey. The roadmap wanted to graduate it
with a 1-second toggle window: each restore-toast in the chain carries
its own Undo, letting users flip-flop a hotkey assignment without
going back to the MIDI panel.

**Lib:** New in midiPresets.js:
- `UNDO_CHAIN_MS = 1000` constant — toggle window in ms. 1 second
  chosen so an interrupted flip-flop ("wait, was it on A or B?")
  still works but the chip doesn't outlive its association with the
  original change.
- `isWithinUndoWindow(issuedAt, now, window?)` pure projector. Endpoint
  invariants: `≤` comparison (click at exact edge counts in-window so
  rapid clicks don't lose to the boundary). Defensive contract:
  non-finite issued/now → false (corrupt timestamps must NOT silently
  let an expired action fire), negative delta → false (system clock
  jumped back), non-finite/negative window arg → false (no implicit
  fallback when caller supplies bad input). Zero window → only an
  exactly-at-issue-time click.

**UI:** `showHotkeyTransferToast(winner, loser, hotkey, prevList)`
internal recursive helper renders one step of the chain. Captures
`issuedAt = Date.now()` inside the closure so each step has its own
fresh window. On Undo: gates via `isWithinUndoWindow` → inside window
flips via functional setState (concurrent edits compose safely via
lib's 1-hotkey-1-bundle invariant) → recursively calls itself with
FLIPPED roles (old loser = new winner, old winner = new loser). Past
the window: chip surfaces an explicit "Undo expired — too late to
flip back (1s window)" amber toast instead of silently no-opping.
`setUserBundleHotkey` is now a thin wrapper.

**Tests:** ~30 fresh asserts. Happy path (0/1/500/999ms), edge invariant
(=1000ms in-window), out-of-window (1001/2000/60000ms), negative delta
(clock jumped back → out), non-finite inputs (NaN/Infinity/null/
undefined/string), custom window arg with edge invariants, non-finite/
negative window → false, zero window only at exact issue time.

**Note on lint:** React Compiler flagged `Date.now()` inside the
recursive helper as `react-hooks/purity` (false positive — the helper
runs only from event handlers, never during render, but the compiler
can't trace that across the recursive closure). Resolved with a
targeted `eslint-disable-next-line` + inline comment explaining why.
Baseline preserved.

### R23.31 — Camera path touch chevron drag

**Graduates:** R22.12 (row-only touch-drag for camera path reorder).

**Why:** R22.12 only fired the long-press timer on the row body. Two
complaints surfaced on touch:
- 16×12px chevron buttons are hard to reach with a thumb.
- When the user DID land a long-press on the chevron, releasing fired
  a synthetic click → the chevron's `onClick` moved the view one step
  beyond the drag's intent.

**UI:** `touchDragHandlers(idx, { stopProp = true })` factory returns
all four touch handlers as a spread-ready object. `stopProp=true` on
chevron/button handlers prevents the touch from bubbling to the row's
handlers (each surface owns its lifecycle; the row keeps its own
bindings unchanged so row-body touches still arm the timer the
original way). `suppressNextClickRef.current = true` on touchend AFTER
drag mode fired, cleared by the next click via
`consumeClickIfSuppressed()`. Chevron / restore / delete onClick all
wrap their actions in the guard — drag's synthetic-click no longer
fires moveUp/moveDown/remove/restore by accident. Chevron +
restore-button get `touchAction:'manipulation'`. Chevron tooltip
mentions "long-press to drag on touch" for discoverability.

**Tests:** Pure wire-layer change. R22.12's `resolveTouchTargetIdx` +
`moveView` already pinned in cameraViews.test.mjs.

### R23.32 — Per-field clamp meter threshold overrides

**Graduates:** R22.27 (global clamp meter warn threshold).

**Why:** R22.27 shipped ONE global threshold that applied to every
meter on every attractor's every field. Power users wanted finer
control:
- STRENGTH: rail = silent attractor (force=0). Should be STRICT —
  hitting the rail is structural, not intentional.
- X / Y / Z: rail = attractor at canvas edge. Often intentional
  (corner-placed turbulence, edge vortex). Should be LOOSE.
- RADIUS / RADIUS·log: middle ground.

**Lib:** New in midiMap.js:
- `CLAMP_THRESHOLD_FIELDS` roster — 6 continuous knob fields
  (strength, radius, radiusLog, x, y, z). `enabled` + `type` excluded
  since they render their own bespoke meters (R20.16 type band,
  R15.16 enabled hysteresis toggle).
- `sanitizeClampWarnOverrides(raw)` — defensive: non-object/array →
  empty map, unknown fields dropped, per-field values clamped via
  `sanitizeClampWarnThreshold`, non-finite dropped (not coerced).
- `resolveClampWarnThreshold(field, global, overrides)` — pure
  read-side resolver. Walks per-field → global → DEFAULT chain.
  Per-field value re-sanitized at lookup so a hand-edited / corrupt
  localStorage entry can't land out-of-range.
- `setClampWarnFieldOverride(overrides, field, value)` — setter with
  ref-equal-on-no-op contract. Pass null/undefined as value to CLEAR
  the field's override. Invalid field → input ref unchanged.
  Non-finite value → input ref unchanged.
- `clearAllClampWarnOverrides(overrides)` — wipe-all helper.
- `hasClampWarnFieldOverride(field, global, overrides)` — UI predicate
  returning true only when per-field DIFFERS from global (an override
  duplicating the global has no effective impact → no pip).

**UI:** `clampWarnOverrides` state persisted to
`midi-clamp-warn-overrides-v1` (empty map → key removed). Meter row
now calls `resolveClampWarnThreshold(a.field, clampWarnThreshold,
clampWarnOverrides)` so tier classification + tooltip + edited-pip
flow through the per-field-aware path. `ClampThresholdPopover`
rewritten:
- Scope header with field label.
- GLOBAL slider (cyan, R22.27 baseline) on top.
- PER-FIELD slider (indigo, R23.32) below.
- Both independently editable; global slider opacity dims when a
  per-field override is active so the priority is visually obvious.
- Header pip in cyan when meter reads global, indigo when meter reads
  per-field override.
- New "Use global" button clears the per-field override.
- "Reset" relabelled "Reset global" so the button targets are clear.
- Popover state changed from `attractorId` to `{ attractorId, field }`
  so the per-field controls know whose override to edit.
- Meter tooltip now reports which path drives the live reading
  ("per-field override" / "global override" / "default").

**Tests:** ~70 fresh asserts on the lib helpers covering all entry
points + ref-equal contracts + clamp range + non-finite + invalid
field + composition with `classifyClampProximity`.

## Cake notes

- R23.34's empty-query-returns-input-by-reference contract is the
  unusual call — most filter helpers would return a fresh array.
  Doing it this way lets the carousel render `sorted.map(...)` without
  a special-case branch and keeps the React tree stable across
  filter-on/filter-off toggles (no remount cascade for unrelated
  state changes).
- R23.32's resolver intentionally doesn't whitelist field names on
  the READ path — only the setter does. This lets a hand-edited
  override file still work (the user knows what they're doing), and
  a caller who wants strict whitelist semantics can `sanitize` first
  before reading. The split keeps the resolver pure + tiny.
- R23.35's "past-window surfaces explicit too-late toast" was a taste
  choice: silently no-opping the click would have been confusing
  ("did I click? did it not work?"). The explicit feedback makes the
  toast self-documenting about why the gesture stopped working.
- R23.31's `suppressNextClickRef` flag is a classic touch-DnD pattern
  — synthetic clicks fire on tap-release even after touchmove
  preventDefault, so the click-side guard is necessary. Future
  touch-DnD additions (R23.39 in the queue: touch row by play-order
  badge) can reuse the same wiring.
